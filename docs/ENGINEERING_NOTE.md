# Engineering note — Pactrieve

Pactrieve answers contract questions only from selected PDF/DOCX sources. The central design is that the language model may propose claims and citation markers, but it never decides whether a quotation is authentic. Every displayed “verified” quote is checked against a canonical extracted text with stable UTF-16 offsets using whitespace-tolerant literal matching. Model-supplied page numbers or offsets are ignored. Literal verification proves that the quote exists in the source; it does not prove that the model’s legal interpretation is correct.

Uploads go through signed browser-to-Supabase Storage transfer so large files do not pass through the serverless request body. Extraction rejects unsupported types, empty scans, and many corrupt packages, and records partial unreadability honestly. For long contracts, structure-aware chunking plus lexical retrieval bounds the evidence window. Retrieval coverage is tracked so empty search results become “not established from retrieved evidence,” not fabricated absence.

Chat uses real OpenAI-compatible SSE token streaming. Stop is database-authoritative: cancellation prevents further persistence races and keeps safely accumulated partial text. PDF and DOCX viewers map verified offsets onto rendered text (PDF.js text layer; DOCX semantic leaves). Unmappable but verified quotes fail the highlight path honestly rather than inventing rectangles.

Version comparison first aligns clauses deterministically, then applies a transparent significance rubric (amounts, notice periods, modal verbs, indemnities). Optional LLM enrichment is Zod-validated and grounded; unsupported commentary is dropped. Part C agent research exposes three read-only tools (`search_documents`, `inspect_passage`, `list_document_sections`). The model chooses tools; the server validates arguments, scopes documents, enforces round/time/call budgets, and verifies final citations the same way as ordinary chat. Activity events mirror real tool dispatches.

Tradeoffs remain: OCR is unsupported; rendered PDF order can diverge from extraction; clause alignment is heuristic; the public demo uses a shared access passphrase rather than multi-user accounts; dense commercial PDFs may exceed synchronous processing budgets even when sparse 150-page fixtures succeed. Future work would add durable workers, stronger visual mapping diagnostics, and true multi-tenant authorization if the product left assignment scope.
